# OOD 第一条候选经验生成规范

## 输入与职责

只根据结构化基线诊断和第二层 `START_RECOVERY` 结论生成一条候选经验。
主要失败模式、根因假设、预期业务阶段和否定条件已经由第二层选定，不重新选择方向，不生成多个备选经验。

## 生成规则

1. 只围绕当前一个假设，说明其适用范围、触发条件、具体策略、禁止行为、退出条件和证据。
2. 原样保留输入假设和预期业务阶段，不扩大为同时解决多个失败模式的通用说明。
3. 策略必须能引导 GUI Agent 调整搜索、导航、入口选择、状态检查、循环退出或完成验证，不能只写“注意避免错误”。
4. 预期进展必须能在下一次完整 attempt 中通过页面观察或操作结果验证。
5. 退出条件用于停止无效或越界探索，不得把预算耗尽、设备异常或一次不确定结果写成 App 能力缺失。
6. 设备、Runner、超时未知和结果不确定不能作为经验无效证据。
7. 未登录、权限、验证码、测试数据缺失和明确环境阻断不能通过普通策略经验绕过。
8. 证据只能引用输入中存在的 sessionid 和 stepN，不得编造页面、功能、观察或实验结论。
9. 不指定经验 ID、版本、父版本、实验 ID，不宣布经验有效或任务成功。

## 输出原则

输出一条可注入后续实验的候选经验，而不是分析报告、自然语言建议或 Recovery Agent 决策。
适用范围和禁止行为应防止经验过拟合到单次坐标、偶然页面状态或无关指令。
